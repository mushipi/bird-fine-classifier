# 巨大な教師から蒸留すれば天井は破れるのか — そして「リーク」に殴られる　Part3🦆

## はじめに

[Part2](https://qiita.com/mushipi/items/fb7f4b70b6c58684a5d3) では、Audio Spectrogram Transformer（AST）でカモの鳴き声を分類しながら、`f1 ≒ 0.84` の天井に頭をぶつけ続けた末に「**本当に解くべき問題は分類スコアではなく OOD 検知（未知を弾くこと）だった**」と気づくところまで書きました。

ただ、分類そのものの天井（録音単位 f1 で 0.83 前後）は、依然として残ったままでした。

Part3 の宿題はこれです。

- **別系統の巨大な基盤モデル「Perch2.0」を“教師”にして知識蒸留（Knowledge Distillation, KD）すれば、AST の天井を破れるのでは？**

結論から言うと、**今回もほぼ予想と違う形で決着しました**。しかも今回は、終盤で自分の評価そのものが殴られます。

- 「蒸留すれば伸びる」→ AST では **有意差すら出ない**
- 「じゃあ蒸留は効かないのか」→ 素の弱いモデルで試したら **ハッキリ効いた**。KD は“条件付き”の手法だった
- そして極めつけ、**テスト録音を増やして再評価したら、運用中モデルのスコアが“学習リーク”で膨らんでいた**ことが発覚し、勝敗がひっくり返ります

統計の話と、自分の評価設計を疑う話が半々です。例によって長いので、お茶でも淹れてきてください🍵

> 評価の単位はこの記事を通して **録音単位 macro-F1 ＋ 録音クラスタ bootstrap の 95%CI** です。チャンク単位の点推定は使いません（同じ録音から切り出したチャンクは独立でないため）。

:::note info
**知識蒸留（KD）とは**
大きくて賢い「教師モデル」の出力（各クラスの確率分布＝ソフトラベル）を、小さい/別の「生徒モデル」に真似させる学習法。正解ラベル（0/1）だけでなく「マガモ80%・カルガモ15%…」という教師の“迷い方”まで学べるのが旨味。本記事の教師は鳥特化の基盤モデル **Perch2.0**、生徒は自作の AST（と、後半は素のCNN）です。
:::

## 第1章：別系統の教師という賭け

なぜわざわざ Perch なのか。理由は「**系統の違う相棒**」が欲しかったからです。

私の AST は Google の汎用音声データセット AudioSet で事前学習されています。一方 Perch2.0 は **鳥の声に特化**した基盤モデル（埋め込み 1536 次元）。学習の出自が違えば、間違え方も違うはず。間違え方が違う2人を組ませると、片方が転んでももう片方が支えてくれる——そういう相補性を期待しました。

着手前に「組ませる価値があるか」だけは確かめました。同じテスト録音（231録音）で測ると：

| | 録音単位 f1 |
|---|---|
| AST 単体 | 0.747 |
| 教師 Perch（線形プローブ） | 0.830 |
| アンサンブル（α=0.4 で混ぜる） | **0.844** |

混ぜると両者より上、しかも予測の不一致が 27%。オラクル（毎回正しい方を選べたら）の上限は +0.147 もありました。**相補性は十分ある → GO**。

蒸留のやり方はオーソドックスに、ただし1点だけ慎重にしました。教師の確率は、訓練録音を **録音単位で 5-fold に分け、自分が学習に使っていない fold を予測する（Out-of-Fold）** ことで作っています。教師が訓練録音を“カンニング”した過信ラベルを生徒に渡さないためです。

:::note warn
⚠️ 白状します。この章の最初、私は「AST は教師より大きく劣る（0.747）」と勘違いしていました。実はこの 0.747 は**別の旧データ分割で学習したモデルを、新しいテストで測ってしまった交絡値**でした。同じ条件で学習し直した素の AST は 0.826 で、**教師 Perch（0.830）とほぼ互角**。地味に時間を溶かしました。「AST は弱いから蒸留で底上げ」ではなく「互角の2人を蒸留で揃える」が正しい絵だった、と後で気づきます。
:::

## 第2章：蒸留したのに、有意差が出ない

同じ条件・同じ乱数 seed で、蒸留なし（base）と蒸留あり（KD）の AST を学習して比べました。

| モデル | 録音単位 f1 | 95%CI | eval_loss |
|---|---|---|---|
| C-base（蒸留なし） | 0.8259 | [0.755, 0.879] | 2.229 |
| **C-kd（蒸留）** | **0.8510** | [0.786, 0.899] | **1.672** |
| teacher（Perch・参考） | 0.8304 | — | — |
| ensemble（参考） | 0.8514 | — | — |

一見、いい話です。KD は **教師 Perch（0.830）を超え、アンサンブル（0.851）と同水準**まで来ました。生徒が教師を超えるのは良い蒸留の兆候ですし、eval_loss が 2.229 → 1.672 と大きく下がったのは、モデルの“自信過剰”が抑えられてキャリブレーションが良くなったということです。

…と、勝ち誇りたいところですが、ここで留保が入ります。

> **KD − base = +0.0251、95%CI[−0.0215, +0.0790]。CI が 0 をまたぐ＝統計的に有意ではない。**

差の向きは一貫して正、損失も改善、教師超え。なのに「本当に効いた」と胸を張れない。理由は単純で、**AST がもう天井（教師の 0.83）の近くにいて、伸びしろが小さい**から。+0.025 程度の差は、231録音という解像度のノイズに埋もれてしまうんです。

方向は見えているのに証明できない。このモヤモヤを、次章で別の角度から殴ります。

## 第3章：効くかどうかは「生徒の弱さ」で決まる

天井近くで効果が埋もれるなら、**伸びしろが大きい弱い生徒**に同じ蒸留を当てればいい。効果量が大きく出れば、231録音でも有意になるはずです。

そこで、事前学習なしの素の小さな CNN（0.39M パラメータ、Conv 4層＋GAP＋全結合）を生徒にしました。データセットも教師の確率も KD 損失も評価も**全部そのまま流用**、生徒だけ差し替えです。

| モデル | 録音単位 f1 | 95%CI |
|---|---|---|
| base-CNN（蒸留なし） | 0.4498 | [0.383, 0.507] |
| **KD-CNN（蒸留）** | **0.5977** | [0.521, 0.662] |
| teacher（参考） | 0.8304 | — |

> **KD − base = +0.1478、95%CI[+0.0843, +0.2112]。CI が 0 を除外＝★有意。**

**本当に驚きました。** 録音の内訳を見ると、KD で正解になり base で誤りだった録音が **53**、その逆が 13。差し引き +40 録音ぶん、蒸留がひっくり返しています。チャンク単位の検証データでも 0.478 → 0.590（+0.111）。

これで言えることが2つ。

1. **「Perch を教師にした蒸留は本当に効く」を、初めて統計的に確認できた。** 素の 0.39M CNN が、教師との約 37% の差を埋めました。
2. 第2章の AST の +0.025（非有意）も、**同じ方向・同じ機構の本物の効果**だったと遡って裏付けられた。天井近くで埋もれていただけ。

ついでに、KD のハイパーパラメータ（蒸留の重み λ と温度 T）を CNN を試験台にグリッド探索しました。**12 構成すべてが base を上回り（Δ+0.048〜+0.208）**、特に λ≈1・T≈1〜2 が甘いゾーン。KD はハイパラに対して頑健に効く、と分かりました。

:::note info
**温度 T**：教師の確率を「どれくらい滑らかにして」生徒に見せるか。T を上げると「マガモ80% カルガモ15%」が「マガモ60% カルガモ25%」のように均され、教師の“迷い”の情報が強調される。高すぎると逆にぼやけて効きが落ちる。
:::

> （図1｜弱い CNN は base→KD で +0.148（有意）、強い AST は +0.025（非有意）。**「効果量は生徒の伸びしろで決まる」**に注目。）

## 第4章：天井の AST も、多 seed soup なら有意化する

第2章で AST の KD は「方向は正だが単発では非有意」でした。ならば、**運任せ（seed の引き）を均してしまえばいい**。

まず seed をまたいだ一貫性。42 / 1 / 2 の 3 つで base と KD を学習します。

| seed | base | KD | KD−base |
|---|---|---|---|
| 42 | 0.826 | 0.851 | +0.025 |
| 1 | 0.825 | 0.858 | +0.033 |
| 2 | 0.801 | 0.825 | +0.024 |
| 平均 | 0.818 | 0.845 | **+0.027** |
| SD | 0.011 | 0.014 | **0.004** |

**KD > base が 3/3 seed**。しかも差の SD はわずか 0.004 で、各モデル自体のブレ（SD 0.01〜0.014）よりずっと小さい。つまり **KD の +0.027 は seed の引きに依らず安定して乗る上乗せ**で、運任せではありません。

次に、3 つの seed のモデルを **重み平均（model soup）** で1つに固めます。

| | 録音単位 f1 | 95%CI |
|---|---|---|
| base-soup | 0.8133 | [0.746, 0.867] |
| **KD-soup** | **0.8714** | [0.812, 0.918] |

> **KD − base = +0.0581、95%CI[+0.018, +0.108]。CI が 0 を除外＝★有意。**

KD-soup の 0.8714 は個々の KD 最良（0.858）すら超える、当時の**過去最高の AST**でした。単発では非有意だった AST の KD を、多 seed soup で「本物かつ有意」に格上げできた——と、この時の私は完全に勝った気でいました。

`ast-duck-C-kd-soup`（0.8714）を新しい運用モデルに**昇格**し、OOD ゲートの閾値も再設定し、ドヤ顔で運用に乗せました。

…この章のドヤ顔が、次章で粉砕されます。

## 第5章：そして「リーク」に殴られる

昇格はしたものの、Part2 以来ずっと気にしていた宿題が残っていました。「**テスト録音が少なすぎて、差が有意かどうかの解像度が低い**」問題です。

そこで世界中から B グレードの録音を追加収集し、**全データを分割し直して**（再 split）、base / KD を 3 seed 学習し直しました（これを Cv2 と呼びます）。テスト録音は 69→**289**に増え、薄かった種の枚数も大きく改善。準備は万全のはずでした。

拡大したテスト**全体**（289録音）で全モデルを測ると：

| model | 録音f1 |
|---|---|
| Cprod（運用中の C-kd-soup） | 0.910 |
| Cv2BASE（新・蒸留なし） | 0.908 |
| Cv2KD（新・蒸留あり） | 0.894 |

**全ペア差なし**。「運用中のモデルが最強、わざわざ替える必要なし」——そう結論しかけました。

ここで、ある違和感に手が止まります。**運用中の Cprod は“旧データ分割の訓練録音”で学習している**。今回テストを再分割したのだから、Cprod が昔学習した録音が、新しいテストに紛れ込んでいるのでは？

数えました。

> **旧（train ∪ val）∩ Cv2-test = 130/289 = 45.0%**

**運用モデルのテストの、半分近くが“学習済み録音”でした。** Cprod の 0.910 は、テストの半分をカンニングした膨張値だったわけです。整合性の確認として、クリーンに作った Cv2 モデルは `Cv2-train ∩ Cv2-test = 0`（リークなし）。

そこで、**3つのモデルすべてが一度も学習していない 159 録音**だけで、正直に（honest）測り直しました。

| model | 録音f1 | 95%CI | 対 Cprod 差（同一録音ペア検定） |
|---|---|---|---|
| **Cv2BASEsoup（蒸留なし）** | **0.897** | [0.704, 0.951] | **+0.110 [+0.042, +0.172] ★有意** |
| Cv2KDsoup（蒸留あり） | 0.822 | [0.625, 0.890] | +0.034 [−0.051, +0.108] 差なし |
| Cprod（運用中） | 0.787 | [0.613, 0.843] | — |

景色が反転しました。

- **運用中モデルの本当の実力は 0.787**。全体評価の 0.910 から **Δ≈0.12 も過大評価**していた。
- クリーンに学習した **蒸留なしの Cv2BASEsoup（0.897）が、運用中を +0.110 で有意に上回る**。
- そして駄目押し。**KDsoup − BASEsoup = −0.076 [−0.164, −0.015] で有意**。**クリーンな土俵では、蒸留“なし”の方が上**だったのです。

第4章で「KD-soup が過去最高！」とドヤっていた優位は、リークの混じった土俵での話でした。クリーンな土俵で効いていたのは蒸留ではなく、**データを増やしてクリーンに分割し直したこと**だったのです。

> （図2｜旧 train∪val と Cv2-test のベン図。重なり 130/289=45%。**この重なりが Cprod のスコアを膨らませていた**ことに注目。）
> （図3｜全体評価（リーク込み）では Cprod 最強に見えるが、honest 評価で順位が反転する様子。）

## まとめ：Part3 で学んだこと

**うまくいかなかったこと**
- 「巨大な教師から蒸留して AST の天井を破る」は、**最終的に否定された**。クリーンな評価では蒸留なしの方が有意に上で、天井近くの強いモデルに KD は乗らなかった。
- テスト拡大という“正攻法”の最初の評価は、全モデル差なしに見えた。危うく「現状維持」で終わるところだった。

**うまくいったこと**
- **素の弱い CNN で、KD の有効性を統計的に確定できた（+0.148, 有意）**。「効く/効かない」を生徒の伸びしろで切り分けられた。
- 多 seed soup で、埋もれていた効果の存在を整理できた。
- そして何より、**自分の運用モデルのリークを暴いて、判定を正せた**。

一番の教訓は、Part2 の「閉じた世界で評価するな」の、さらに深いところにありました。

> **モデルの昇格判定は、必ず「そのモデルが一度も見ていない録音」で行え。**
> 0.910 と 0.787 を分けたのは、手法でもハイパラでもなく、**テストに学習が漏れていたかどうか**だった。手元のスコアは、いつの間にか自分に都合よく膨らむ。

最後に、KD の価値を**再定義**しておきます。精度を底上げする万能薬ではありませんでした。効くのは **(a) 弱い生徒・低データのとき**、そして **(b) seed のブレを縮めるとき**。でも、もう一つ、地味だけど効く価値があります。

> **(c) 推論時に教師（重い Perch）が要らない。** 蒸留済みの AST 単体なら CPU でも動く。

この (c) が、次回の伏線です。

### Part4 に向けて

分類のコアは、蒸留なしの新モデル（`ast-duck-D-base-soup`、honest 0.897）に落ち着きました。次はいよいよ **1個のモデルを“運用システム”にする**話です。

- BirdNET（汎用検出）→ Dispatcher → 群専用 Stage2 → Energy ゲート、という **2段パイプライン**
- 蒸留が効いた本当の理由＝**GPU なしの CPU 運用機にデプロイできること**
- そして、データを増やしても精度で殴っても**絶対に割れない種のペア**（カルガモ問題）と、それを「設計」で受け止める話

エッジデバイスは…買いませんでした。CPU で足りたので。Part4 をお楽しみに🦆

間違いやツッコミ、「そのリークの解釈おかしくない？」みたいな指摘があれば、ぜひコメントで教えてください。
